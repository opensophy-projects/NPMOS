# Решение проблем

## Браузер перенаправляет на другой адрес, хотя редиректа в NPMOS нет

### Признаки

- Домен открывается не там, где должен: например, `npmos.example.com` перекидывает на `example.com`.
- В NPMOS для этого домена нет хоста-редиректа, или NPMOS вообще переустановлен с нуля.
- Удаление хостов, томов и переустановка не помогают.

### Почему так

Ответ `301 Moved Permanently` браузер кэширует **навсегда** и при следующем открытии перенаправляет сам, даже не обращаясь к серверу. Если раньше на этом домене был редирект (хост-редирект, «Сайт по умолчанию → редирект», другой прокси), браузер помнит его и после того, как редирект убрали на сервере. Удаление NPMOS этот кэш не трогает.

Похоже ведёт себя HSTS: после ответа с `Strict-Transport-Security` браузер открывает домен только по HTTPS, пока не истечёт срок политики.

### Как убедиться, что дело в браузере

1. Спросите сам NPMOS, мимо DNS и кэша браузера:

   ```bash
   curl -skI https://npmos.example.com --resolve npmos.example.com:443:127.0.0.1
   ```

   Если в ответе нет заголовка `location:`, NPMOS не перенаправляет. `127.0.0.1` замените на адрес сервера NPMOS, если проверяете с другой машины.

2. Проверьте, куда указывает DNS, и что отвечает домен из интернета:

   ```bash
   getent hosts npmos.example.com
   curl -sI https://npmos.example.com | grep -i '^location'
   ```

   Если IP не ваш, а `location` есть, перенаправляет другой сервер: исправьте DNS-запись.

3. Откройте адрес в окне инкогнито. Там нет кэша: если открывается правильно, дело в браузере.

Если `location` нет ни в одной из проверок, а обычное окно браузера всё равно перекидывает, причина — кэш браузера.

### Как исправить

**Chrome, Edge, Chromium, Яндекс Браузер**

- `chrome://settings/clearBrowserData` → период «Всё время» → «Изображения и другие файлы в кэше» → «Удалить данные». Кэшированный 301 хранится именно там.
- Точечно, без очистки всего кэша: F12 → вкладка Network → галочка «Disable cache». Не закрывая DevTools, откройте адрес: новый ответ сервера заменит старый редирект.
- HSTS: `chrome://net-internals/#hsts` → «Delete domain security policies» → домен → «Delete».

**Firefox**

- «Настройки → Приватность и защита → Куки и данные сайтов → Удалить данные» → «Кэшированное веб-содержимое».
- Или «Журнал» → правый клик по сайту → «Забыть об этом сайте». Это удаляет и кэш, и HSTS домена.

**Safari**

- «Разработка → Очистить кэши». Если меню «Разработка» нет, включите его: «Настройки → Дополнения».

**Автодополнение адреса**

Иногда перекидывает не кэш, а подсказка в адресной строке: браузер подставляет ранее открытый `example.com` вместо набранного `npmos.example.com`. Наберите адрес целиком, с `https://`. Лишнюю подсказку в выпадающем списке удалите: Shift+Delete в Chrome, Delete в Firefox.

### Как не попасть в это снова

- Для временных и тестовых редиректов используйте код `302` или `307`, а не `301`/`308`. Временные редиректы браузер не запоминает. Код задаётся в настройках хоста-редиректа.
- Перед включением HSTS убедитесь, что домен останется на HTTPS. Браузер будет требовать HTTPS до конца срока политики, даже если HSTS потом выключить.
