# Перенос с Nginx Proxy Manager, NPMplus и open-appsec-npm

Перенос делается в интерфейсе: **Администрирование → Настройки → Перенос**. Старая установка при этом не меняется: NginxionS читает копию её данных. Пока DNS или порты не переключены, старый контейнер можно держать запущенным, а при неудаче вернуться к нему.

## Что переносится

| Данные | Как |
|---|---|
| Прокси-хосты, перенаправления, хосты 404, потоки, локации | Как есть, с теми же номерами. Конфиги nginx генерируются заново. |
| Сертификаты Let's Encrypt | Строки из базы и файлы certbot (`accounts`, `archive`, `renewal`). `live/` создаётся заново ссылками на последние файлы, пути в `renewal/*.conf` переписываются на пути NPMplus. Продление продолжается в NginxionS. |
| Свои сертификаты | Из базы: NPM и NPMplus хранят их вместе с ключами. Файлы из `custom_ssl` / `tls/custom` переносятся, если они есть. |
| Списки доступа | Строки из базы, файлы htpasswd генерируются заново. NPM хранит пароли открытым текстом, при переносе они хешируются bcrypt. Старые пароли продолжают работать. |
| Пользователи | Со старыми паролями (хеши bcrypt) и 2FA. Пользователь, чей email уже есть в NginxionS, остаётся как был и сопоставляется по email. |
| Права пользователей | Становятся ролями NginxionS так же, как при обновлении NPMplus → NginxionS: одинаковые наборы прав дают одну роль. Администраторы остаются администраторами. |
| Сайт по умолчанию | Настройка и страница `html/` (`nginx/default_www` у NPM). |
| Свои сниппеты nginx | `nginx/custom/*.conf` (NPM) или `custom_nginx/*.conf` (NPMplus). Если nginx их не принимает, возвращаются прежние, и об этом выводится предупреждение. Можно отключить галочкой. |
| WAF-правила open-appsec-npm | Режим и минимальная уверенность из `local_policy.yaml` для хостов и локаций (`npm-managed-specific-rule-proxyhost-<id>`). |
| Журнал аудита | По желанию (галочка). |

Не переносятся:

- **Логи.** Они при чтении архива пропускаются.
- **Сгенерированные конфиги nginx.** Они создаются заново.
- **Ключи JWT** (`keys.json`). Пользователям нужно войти заново.
- **Настройки CrowdSec и Anubis из NPMplus.** CrowdSec в NginxionS свой и настраивается в разделе «CrowdSec».
- **env-настройки старого контейнера** (TZ, порты и т.п.). Их задают в «Администрирование → Настройки».

## Почему только в новый NginxionS

Номера хостов, сертификатов и списков доступа сохраняются: по ним названы файлы certbot (`npm-<id>`) и WAF-правила open-appsec-npm. Поэтому в NginxionS к началу переноса не должно быть ни одного хоста, сертификата или списка доступа, в том числе удалённых. Если они есть, страница их перечислит и импорт не запустится.

Порядок такой:

1. Развернуть NginxionS.
2. Создать первого администратора.
3. Сразу перейти к переносу.

## Источники

### Архив (основной способ)

Сначала остановите старый контейнер: SQLite должна дописать базу. NPMplus держит последние изменения в `database.sqlite-wal`; этот файл тоже берётся из архива, но остановка надёжнее.

Nginx Proxy Manager и open-appsec-npm:

```bash
docker compose stop        # в каталоге старой установки
tar czf npm-backup.tgz -C /путь/к/npm data letsencrypt
# open-appsec-npm: добавьте каталог с local_policy.yaml, например appsec-localconfig
```

NPMplus:

```bash
docker compose stop
tar czf npmplus-backup.tgz -C /путь/к/npmplus/data .
```

Пути в архиве могут быть любыми (`./`, `data/`, `npm/data/`): база, `letsencrypt` и остальное находятся по именам.

Из архива извлекается только нужное:

- `database.sqlite(-wal)`;
- файлы certbot;
- `custom_ssl` / `tls/custom` / `tls/mtls`;
- `nginx/custom` / `custom_nginx`;
- `html` / `nginx/default_www`;
- `local_policy.yaml`.

Логи и прочее пропускаются. Ограничения:

- архив до 2 ГБ, извлечённые файлы до 1 ГБ;
- только обычные файлы и каталоги;
- символические и жёсткие ссылки, устройства и пути с `..` не записываются.

Можно загрузить и один `database.sqlite`, но тогда у сертификатов Let's Encrypt не будет файлов. Страница предупредит: их придётся перевыпустить.

### База MySQL/MariaDB или PostgreSQL по сети

Для NPM, работающего с внешней базой. Нужно указать адрес, порт, имя базы, пользователя и пароль. NginxionS один раз читает базу в свою копию и ничего в ней не меняет; достаточно пользователя с правом чтения. База должна быть доступна из контейнера `nginxions`. Если её порт не опубликован, временно опубликуйте его или подключите контейнер базы к сети NginxionS.

После подключения загрузите ещё архив `data` и `letsencrypt`, чтобы перенести файлы сертификатов и сниппеты.

## Что происходит при переносе

1. **Анализ.** База копируется во временный SQLite (`/data/nginxions/migration`), и к копии применяются миграции NPMplus. У NPM они те же самые, поэтому база любой версии NPM доводится до схемы NginxionS. После этого страница показывает:
   - что найдено: NPM, NPMplus или open-appsec-npm и сколько миграций выполнено;
   - сколько будет перенесено хостов, сертификатов и списков доступа;
   - список пользователей;
   - предупреждения;
   - что мешает переносу.
2. **Импорт.** Всё пишется в базу NginxionS одной транзакцией: если что-то не так, в базу ничего не попадёт. Затем:
   - переносятся файлы;
   - генерируются конфиги nginx для всех хостов (с проверкой `nginx -t`) и политика WAF.
3. **Результат.** Страница показывает:
   - сколько перенесено;
   - какие пользователи уже были в NginxionS;
   - сколько паролей захешировано;
   - хосты, которые nginx не принял.
4. **«Завершить»** удаляет рабочие файлы. В них были ключи сертификатов, поэтому не оставляйте их.

Если у сертификатов DNS-проверка, перезапустите NginxionS («Обзор → Сервисы»). При старте certbot получает DNS-плагины и файлы учётных данных.

## После переноса

1. Проверьте хосты: формы NPMplus отличаются от NPM, некоторые параметры названы иначе.
2. Если NginxionS работает за другим NPM/NPMplus, у этого прокси схема должна быть https.
3. Переключите DNS или порты 80/443 на NginxionS и остановите старый контейнер.
4. Включите WAF и CrowdSec для хостов. Для open-appsec-npm режимы WAF уже перенесены.
5. Проверьте пользователей и роли («Администрирование»). Роли «Imported permissions» можно переименовать.

## Права

Нужны права `settings:manage`, `users:manage` и `roles:manage`, так как переносятся пользователи с их ролями. На практике это администратор.

## Проверено

- **Nginx Proxy Manager 2.16 (SQLite).** Прокси-хост со своим сертификатом, списком доступа (IP и логин) и локацией, хост с Let's Encrypt, перенаправление, хост 404, поток, сайт по умолчанию, сниппет `server_proxy.conf`. Пользователь с ограниченными правами стал ролью. Basic auth со старым паролем работает, сертификаты отдаются, сниппет применяется.
- **NPMplus 2026-10-14 (SQLite в режиме WAL).** Хост со списком доступа (`npmplus_access_list_ids`). Пароли уже захешированы и не хешируются повторно.
- **Nginx Proxy Manager 2.16 с PostgreSQL** по сети и файлами из архива.
- **open-appsec-npm.** Правила `prevent-learn` / `critical` и `inactive` из `local_policy.yaml` стали настройками WAF хостов.
- **Smoke-тест закрытого контура** (`deploy/test/smoke.sh`). Архив NPM (`deploy/test/fixtures/npm-backup.tgz`) читается, распознаётся и анализируется; импорт в NginxionS с хостами отклоняется.
- **MySQL/MariaDB** использует тот же код копирования, что и PostgreSQL (knex), но на живой MariaDB не проверялась.

## Обновление стека, установленного под названием NPMOS

Проект раньше назывался NPMOS: compose-проект `npmos`, тома `npmos_*`, таблицы `npmos_*`, каталог `/data/npmos`.
Перенос на NginxionS:

```bash
docker compose -p npmos -f deploy/compose.yaml down   # остановить старый стек (тома остаются)
scripts/upgrade-from-npmos.sh                         # копирует тома npmos_* в nginxions_*, переименовывает
                                                      # секреты, роль и базу Postgres
docker compose -f deploy/compose.yaml up -d
```

Остальное NginxionS делает сам при первом запуске: переименовывает таблицы и записи миграций в базе, имена
встроенных объектов WAF и ключи в JSON (`nginxions/backend/nginxions/rename.js`), переносит `/data/npmos` в
`/data/nginxions` вместе с путями в конфигурациях хостов. Старые тома скрипт не трогает: удалите их, когда
NginxionS заработает (`docker volume rm $(docker volume ls -q --filter name=^npmos_)`).
