# Политика WAF: руководство пользователя

Как настраивать защиту сайтов агентом open-appsec в NginxionS: из чего состоит политика, как включить WAF на хосте,
как писать исключения, ограничивать частоту запросов, проверять изменения до применения, откатывать их и учить
агента. Всё делается в интерфейсе — файлы руками не правятся.

Устройство и решения для разработчиков — в [WAF-POLICY.md](WAF-POLICY.md), обучение — в
[adr/0011-learning.md](adr/0011-learning.md).

## 1. Коротко

- WAF включается **на каждом хосте отдельно** (окно хоста, раздел WAF). Хосты без WAF не проверяются.
- Политика собирается из **блоков** (объектов): защита от атак, журналирование, ответ на блокировку, исключения,
  ограничение частоты, доверенные источники, идентификаторы источника. Блок создаётся один раз и используется в
  любом числе хостов.
- Есть **базовая политика** (для всего, что хост не задаёт сам) и **политика хоста** (режим, уверенность и свои блоки).
- NginxionS сам пишет файл политики агента `local_policy.yaml` (формат **v1beta2**) и просит агента применить
  его. Обычно изменение действует через несколько секунд.
- Перед применением видно, **что изменится** в файле и **как изменение повлияло бы на события WAF за последние
  24 часа** (пробный прогон).
- Каждое изменение сохраняется **версией**; любую версию можно вернуть.
- Новый сайт начинают в режиме **обнаружения с обучением** и переводят в **блокировку**, когда агент обучен:
  с проверкой «что было бы» за 7 дней или пробным режимом на несколько часов.

## 2. Быстрый старт

1. **Хосты** → откройте proxy-хост → раздел **WAF** → **Защищать с помощью open-appsec**.
2. **Режим защиты**: **Detect-Learn** (атаки только записываются, агент учится). Минимальная уверенность —
   **Высокая**. **Объекты политики** — **Как в базовой политике**. Сохраните.
3. Через несколько секунд хост защищён. Атаки видны в **Аналитика → События** (и в **Блокировки**).
4. Пусть сайт поработает несколько дней. В **Агенты → open-appsec → Обучение** видно, насколько агент обучен,
   и очередь запросов, в которых он не уверен: разметьте их («Ложное срабатывание» / «Атака»).
5. Когда агент обучен: **Обучение** → у хоста **Перевести в блокировку** (сначала покажет, что блокировка
   сделала бы с событиями за 7 дней) или **Пробный режим** на 1 час…7 дней.
6. Если блокируется лишнее — исключение (раздел 8) прямо из события: **Создать исключение**.

## 3. Где что находится

| Где | Что |
|---|---|
| **Хосты** → окно хоста → **WAF** | Включить WAF, режим, минимальная уверенность, блоки хоста; то же для отдельных location |
| **Агенты → open-appsec → Политики** | Базовая политика, политики хостов, все блоки, импорт и экспорт, **Дополнения YAML**, **Версии** |
| **Агенты → open-appsec → Агент** | Состояние агента, «Показать YAML» (что записано), «В агенте» (что агент применил), настройки агента, метрики |
| **Агенты → open-appsec → Обучение** | Очередь разметки, готовность хостов, «Что выучено», **Пробный режим**, **Перевести в блокировку**, **Снимки обучения** |
| **Аналитика → События** | События WAF; в карточке события — разметка и **Создать исключение** |
| **Агенты → Страница блокировки** | Как выглядит страница, которую видит заблокированный посетитель |
| **Администрирование → Уведомления** | Правила уведомлений, в том числе об окончании пробного режима и о резком сдвиге обучения |

Страница **Политики** переключается между видом **Интерфейс** и **Код** (YAML того же).

## 4. Из чего состоит политика

```
Базовая политика ──┐                       ┌── Защита от атак (практика)
                   ├─ ссылается на блоки ──┼── Журналирование
Политика хоста A ──┤                       ├── Ответ на блокировку
Политика хоста B ──┘                       ├── Исключения
                                           ├── Ограничение запросов
                                           ├── Доверенные источники
                                           └── Как узнать клиента (идентификаторы источника)
```

- **Базовая политика** действует для всего, что хост не задаёт сам. Её режим обычно **Неактивен**: WAF включается
  в каждом хосте. **Исключения базовой политики действуют на все хосты** (вместе с исключениями хоста).
- **Политика хоста** — режим, минимальная уверенность и, если нужно, свои блоки. Хост, у которого блоки «как в
  базовой политике», берёт их из неё.
- **Встроенные блоки** NginxionS (помечены «встроенный») обновляются вместе с NginxionS и не редактируются;
  нажмите **Копия**, чтобы сделать свой на их основе:

| Встроенный блок | Что делает |
|---|---|
| Защита от атак: рекомендуемая | ML-проверка веб-атак с обычными лимитами; подходит большинству сайтов |
| Защита от атак: строгая | Блокирует с меньшей уверенностью и проверяет больше: меньше пропусков, больше ложных срабатываний |
| Защита от атак: API | Для JSON API: дополнительно отклоняет недопустимые HTTP-методы |
| Журналирование: атаки в NginxionS | Обнаруженные и заблокированные запросы пишутся в журнал, который читает NginxionS |
| Ответ: код 403 | Заблокированный запрос получает 403 и страницу блокировки NginxionS |
| Ответ: страница блокировки агента | Страница с заголовком и текстом |
| Без ограничения запросов | Частота не ограничивается |

Имя блока — строчные латинские буквы, цифры, `.`, `_`, `-`; оно попадает в `local_policy.yaml`.
Блок, который используется хотя бы в одной политике, удалить нельзя — сначала уберите его из политик.

## 5. Политика хоста

Окно хоста → **WAF**:

- **Защищать с помощью open-appsec** — включает проверку хоста.
- **Режим защиты** и **Минимальная уверенность** — раздел 6.
- **Объекты политики**:
  - **Как в базовой политике** — блоки базовой политики;
  - **Свои объекты** — выберите практику, журналирование, ответ, исключения, ограничения частоты, доверенные
    источники, идентификаторы источника для этого хоста;
  - **Шаблон: …** — быстро заполнить из шаблона (Рекомендуемый, Строгий, API, Только наблюдение).
- **Location** хоста могут наследовать настройки хоста или иметь свои (включить/выключить WAF, режим,
  уверенность) — например, строже для `/admin` или выключить для `/health`.

То же доступно в **Агенты → open-appsec → Политики** → политика хоста.

## 6. Режимы и уверенность

| Режим | Блокирует | Учится | Когда |
|---|---|---|---|
| **Detect-Learn** (Обнаруживать и обучаться) | нет, только журнал | да | Новый сайт, первые дни |
| **Prevent-Learn** (Блокировать и обучаться) | да (ответ из блока «Ответ») | да | Рабочий режим |
| Обнаруживать / Блокировать | как выше | нет | Особые случаи в блоках |
| Неактивен | нет | нет | Базовая политика, выключенные location |
| Как у правила | — | — | В блоках: брать режим хоста |

**Минимальная уверенность** (Критическая / Высокая / Средняя) — насколько агент должен быть уверен, что это атака,
чтобы заблокировать. **Высокая** — обычный выбор. **Средняя** блокирует больше (и больше ложных срабатываний),
**Критическая** — только самые явные атаки.

## 7. Блоки политики

### Защита от атак (практика)
**Веб-атаки (ML)**: режим, минимальная уверенность, лимиты размера тела, заголовка, URL и вложенности объектов,
защиты — CSRF, раскрытие ошибок, открытое перенаправление, **нестандартные HTTP-методы**.
**Сигнатуры Snort**: режим и файлы сигнатур в агенте (по одному в строке; применяются все).
**IPS, Anti-Bot, Schema Validation, File Security**: дополнительные движки практики. В open-appsec они есть только
в Premium, в NginxionS работают без интернета (раздел 20).

### Журналирование
Какие события пишутся: заблокированные, обнаруженные, все запросы (много данных); подозрительные запросы с
минимальной серьёзностью, кодом и телом ответа; подробности (путь и параметры URL, заголовки, тело запроса);
отправка на внешний **Syslog** / **CEF** (сколько угодно серверов: IPv4, IPv6 или имя, порт, TCP/UDP; один
IPv4-сервер агент обслуживает сам, остальные — через ретранслятор NginxionS).
NginxionS сам читает журнал агента — для «Событий» внешний сервер не нужен.

### Ответ на блокировку
Раздел 10.

### Исключения
Раздел 8.

### Ограничение запросов
Раздел 9.

### Доверенные источники
Клиенты, на чьём трафике агент учится как на нормальном (офис, мониторинг), и **минимальное число источников**,
от которого их трафик считается нормой. Это и защита обучения: агент быстрее учится на доверенных и не
выучивает чужое как норму.

### Как узнать клиента (идентификаторы источника)
Как агент различает клиентов за прокси или CDN: по IP, `X-Forwarded-For`, заголовку, cookie или полю JWT.
Влияет на обучение (сколько «разных источников» прислали значение) и на ограничение частоты по источнику.

## 8. Исключения

Исключение — правило «эти запросы обрабатывать иначе». Состоит из **действия** и **условий**.

**Действия:**

| Действие | Что делает |
|---|---|
| **Пропускать (accept)** | Запрос не блокируется WAF |
| **Отбрасывать (drop)** | Запрос всегда блокируется |
| **Не проверять (skip)** | Запрос не проверяется |
| **Не журналировать (suppressLog)** | Запрос обрабатывается как обычно, но не пишется в журнал |

**Поля условий:** IP или сеть источника, URL, имя хоста, имя параметра, значение параметра, защита, код страны,
страна, идентификатор источника и — расширения NginxionS — **метод**, **имя заголовка**, **значение заголовка**,
**место параметра**, **индикатор атаки**.

**Операторы:** **равно** (по умолчанию), **не равно**, **есть** (у поля есть любое значение; значение не нужно).
В YAML доступны также `in` и `not-in` (то же, что «равно» и «не равно» со списком).

**Как сочетаются условия:**
- несколько условий **одного поля с «равно»** — подходит **любое** из значений (ИЛИ);
- несколько условий **одного поля с «не равно»** — не подходит **ни одно** из значений;
- условия **разных полей** — должны выполняться **все** (И).

Примеры:

| Задача | Действие | Условия |
|---|---|---|
| Пропускать офис | Пропускать | IP источника = `203.0.113.0/24` |
| Не проверять health-check | Не проверять | URL = `/health` |
| Ложное срабатывание в поле поиска | Пропускать | URL = `/search`, имя параметра = `q` |
| Блокировать всех, кроме своей страны | Отбрасывать | код страны не равно `RU` |
| Пропускать только мониторинг с заголовком | Пропускать | имя заголовка = `x-monitoring`, IP = `10.0.0.5` |
| Блокировать запросы с отладочным заголовком | Отбрасывать | имя заголовка = `x-debug` |
| Пропускать всё, кроме одного IP | Пропускать | IP источника не равно `192.0.2.7` |

Имена и значения заголовков сравниваются в нижнем регистре.

**Где исключение действует:** в базовой политике — на все хосты; в политике хоста — только на него.
Быстрый путь: **Аналитика → События** → событие → **Создать исключение** (поля заполнятся из события; исключение
добавится и в базовую политику).

**Экспорт:** исключения с расширениями NginxionS (новые поля и операторы) не входят в экспорт v1beta1; в v1beta2
они остаются, но чужой агент open-appsec прочитает оператор как «равно» и не поймёт новые поля — файл об этом
предупреждает.

## 9. Ограничение частоты запросов

Блок **Ограничение запросов** (контроль доступа): **режим** и **правила**. Правило:

- **URI** — путь (например, `/login`);
- **Лимит** и **Период** (в секунду / в минуту) — сколько запросов разрешено одному клиенту;
- **Действие** — блокировать или только записывать (если не задано — как режим блока);
- **Условия** — к кому правило применяется: IP или сеть, URL, идентификатор источника, страна.

Клиент сверх лимита получает ответ из блока «Ответ на блокировку» политики хоста (например, код 429).

Клиент — как его различает блок «Как узнать клиента» (по умолчанию IP). Пример: 10 запросов в минуту на
`/login` → перебор паролей упирается в лимит, остальной сайт работает как обычно. После окончания периода путь
снова доступен.

## 10. Ответ на блокировку

| Тип | Что получает посетитель |
|---|---|
| **Только HTTP-код** | Код (например 403 или 406) и страница блокировки NginxionS |
| **Страница блокировки** | Страница со своим заголовком и текстом, с указанным кодом |
| **Перенаправление** | Переход на ваш URL; можно добавить идентификатор события (X-Event-ID), чтобы поддержка нашла его в «Событиях» |

Оформление страницы блокировки NginxionS настраивается отдельно: **Агенты → Страница блокировки**.

## 11. Как изменения применяются

1. Вы меняете блок или политику и нажимаете **Просмотреть изменения**.
2. Окно предпросмотра показывает:
   - **Изменения local_policy.yaml** — что именно поменяется в файле агента;
   - **Пробный прогон на событиях WAF за последние 24 часа** — сколько событий обработалось бы иначе:
     пропущено / заблокировано / только записано, с группами по хосту и пути. ML-анализ не повторяется:
     событие сохраняет свою уверенность. Условия, которых нет в событиях (страна, заголовки), отмечаются как
     «нельзя оценить»;
   - **предупреждения** — например, ссылка на несуществующий блок или настройка, которая в агенте ничего не делает.
3. **Применить** — NginxionS записывает `local_policy.yaml` и просит агента применить его (обычно секунды; если
   агент не ответил — он подхватит файл сам в течение 30 секунд).
4. **Агенты → open-appsec → Агент**, строка **В агенте**: NginxionS сверяет, что агент применил политику так, как
   она записана (хосты, ответы, ограничения частоты). Расхождение показывается там же.

## 12. Версии и откат

**Агенты → open-appsec → Политики → Версии**: каждое изменение (создан/изменён/удалён блок, базовая политика,
импорт) — отдельная версия. **Вернуть** восстанавливает блоки, базовую политику и блоки хостов к выбранной версии;
откат сам сохраняется новой версией, так что его тоже можно отменить. Дополнительно NginxionS хранит 20 последних
файлов `local_policy.yaml` в томе данных (`/data/nginxions/waf/policy-backups`).

## 13. Импорт и экспорт local_policy.yaml

**Экспорт** — YAML блоков и базовой политики: **v1beta2** (полный) или **v1beta1** (для старых агентов; что в него
не входит, перечислено в заголовке файла). Можно выгрузить и один раздел.

**Импорт** — файл `local_policy.yaml` (v1beta1 или v1beta2), например от open-appsec-npm или из документации
open-appsec:

1. **Импорт** → вставьте YAML или выберите файл → **Проверить**.
2. План покажет: сколько блоков будет создано и обновлено, какие встроенные пропущены, что не импортируется
   (Kubernetes, облако Check Point, движки Premium, лишние практики правила) и что базовая политика будет заменена.
3. **Импортировать**. Правила хостов из файла не импортируются — хосты выбирают блоки в своих настройках WAF.

## 14. Дополнения YAML (эксперт)

**Агенты → open-appsec → Политики → Дополнения YAML** — фрагмент `local_policy.yaml`, который NginxionS
накладывает поверх того, что генерирует сам. Нужен только для того, для чего в интерфейсе нет поля.
**Проверить** покажет изменения файла, **Сохранить и применить** — применит. У фрагментов свои версии и откат.
Если во фрагменте ошибка, «Проверить» покажет её до сохранения.

## 15. Обучение агента и переход в блокировку

**Агенты → open-appsec → Обучение:**

- **Очередь** — группы запросов, в которых агент не уверен (заблокированные или со средней оценкой). Разметка:
  **Ложное срабатывание** (легитимно; можно сразу добавить исключение на срок) или **Атака** (не учиться на этом;
  можно забанить источник в CrowdSec). Агент читает разметку раз в минуту, исключение действует сразу.
  Разметку можно отменить в истории.
- **Хосты** — готовность обучения каждого хоста, **Что выучено** (нормальные значения параметров по мнению агента),
  **Перевести в блокировку**, **Пробный режим**.
- **Перевести в блокировку** сначала показывает, что блокировка сделала бы с событиями хоста за 7 дней.
- **Пробный режим** (1 час, 6 часов, 24 часа, 3 дня, 7 дней): хост остаётся в обнаружении, ничего не блокируется,
  а NginxionS оценивает его события так, как их обработала бы блокировка. Отчёт виден во время пробы; по окончании
  приходит уведомление «Пробный режим блокировки завершён», и хост переводится в блокировку одной кнопкой.

## 16. Снимки обучения

Обучение — это то, что агент считает нормой для каждого сайта. Его можно «отравить»: медленно и со многих адресов
приучать агента считать атаки обычным трафиком. **Снимки обучения** (кнопка на странице «Обучение») — точки
восстановления выученного:

- NginxionS делает снимок **раз в сутки** (хранятся последние 14) и **по кнопке**;
- каждый снимок сравнивается с предыдущим: если выученное по сайту **резко выросло или уменьшилось** (не меньше
  чем на 30 значений и на половину), на странице «Обучение» появляется предупреждение, а правило уведомлений
  «Резкий сдвиг выученного WAF» сообщает об этом;
- **Восстановить** — вернуть агенту выученное из снимка; текущее состояние сначала сохраняется снимком «Перед
  откатом». Агент и NginxionS перезапускаются (около минуты без WAF);
- **Скачать** / **Загрузить снимок** — перенос обучения на другой сервер NginxionS (после загрузки нажмите
  «Восстановить»). Снимки лежат в томе данных NginxionS, поэтому входят в его резервную копию.

Как ещё снизить риск отравления: **доверенные источники** и **идентификатор источника по пользователю** (сессия,
JWT) вместо IP — раздел 7.

## 17. Права доступа

| Право | Что даёт |
|---|---|
| `waf_policy:view` | Смотреть политику, блоки, версии, YAML |
| `waf_policy:manage` | Менять блоки и политики, импорт, дополнения YAML, откат, восстановление и загрузка снимков обучения |
| `waf_policy:apply` | Применить политику вручную |
| `waf_learning:view` | Смотреть обучение и снимки |
| `waf_learning:label` | Размечать, делать и скачивать снимки |
| `proxy_hosts:update` (или `waf_policy:manage` вместе с правом видеть хост) | Включать WAF на хосте и менять его режим, запускать и закрывать пробный режим |

Встроенные роли: **Operator** и **Security Analyst** управляют политикой, **Viewer** только смотрит.

## 18. Типовые задачи

- **Ложное срабатывание на одной странице.** Событие → **Создать исключение** → оставьте URL и имя параметра,
  уберите лишнее → предпросмотр (пробный прогон покажет, сколько запросов перестанет блокироваться) → Применить.
  Или разметьте событие «Ложное срабатывание» в Обучении.
- **Строже для админки.** Location `/admin` хоста → свой режим Prevent-Learn и уверенность Средняя.
- **Защита формы входа от перебора.** Блок «Ограничение запросов»: URI `/login`, 10 в минуту, действие —
  блокировать → подключить к хосту; ответ хоста — блок «Ответ на блокировку» с кодом 429.
- **API.** Шаблон **API** у хоста (отклоняет нестандартные методы).
- **Пускать только свою страну.** Исключение в базовой политике: Отбрасывать, код страны не равно `RU`
  (нужна база GeoIP: **Администрирование → Настройки → GeoIP**).
- **Перенос настроек со старого open-appsec.** Импорт его `local_policy.yaml` (раздел 13).
- **Закрыть известные уязвимости (CVE) старого движка сайта.** Практика → IPS: режим «как у правила», «с года» —
  год старейшей версии, которую стоит закрывать (раздел 20).
- **Отсечь ботов от формы входа.** Практика → Anti-Bot: «Страницы проверки» — `/login`, «Пути с обязательной
  проверкой» — `/api/login` (раздел 20).
- **API только по контракту.** Загрузите OpenAPI-файл в практике → Schema Validation, режим Detect на неделю, затем
  Prevent (раздел 20).
- **Не пускать вирусы в загрузки.** Практика → File Security, предел размера — наибольший размер ваших загрузок
  (раздел 20).
- **Что-то сломалось после изменения.** Политики → Версии → Вернуть.

## 19. Если что-то не работает

- **Изменение не действует.** Агенты → open-appsec → Агент: «Отправлена агенту», «В агенте». Расхождение
  показывается там же; «Применить сейчас» отправит политику повторно.
- **Атака проходит.** Проверьте режим хоста (Detect-Learn только записывает), исключения базовой политики
  (они действуют на все хосты) и минимальную уверенность. В «Событиях» видно, с какой уверенностью агент
  оценил запрос.
- **Блокируется легитимное.** Событие → Создать исключение или разметка «Ложное срабатывание».
- **Предупреждение «настройка ничего не делает».** Поле, которое агент NginxionS не применяет: выключите его.
- **Резкий сдвиг обучения.** Обучение → Снимки обучения: сравните со снимками до сдвига и восстановите ранний,
  если рост не объясняется новыми разделами сайта.

- **Anti-Bot или Schema Validation не действуют.** Нужен включённый баунсер CrowdSec (CrowdSec → Настройки →
  Баунсер): он отправляет запросы в AppSec. Сам AppSec для этих движков включается автоматически.
- **File Security пропускает вирус.** Агенты → open-appsec → Агент → File Security: состояние «Запускается»
  значит, что ClamAV ещё загружает сигнатуры (до минуты-двух после включения), и загрузки пока проходят.
  Проверьте предел размера в практике.

Другие проблемы — [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## 20. Дополнительные движки: IPS, Anti-Bot, Schema Validation, File Security

Все четыре включаются в практике (блок «Защита от атак»): поле «Режим» каждого движка. «Как у правила» —
режим хоста. События всех четырёх видны в «Событиях» вместе с остальными. Как они устроены внутри —
[WAF-POLICY.md](WAF-POLICY.md), раздел 8.

### IPS: сигнатуры известных уязвимостей

Агент проверяет запросы по сигнатурам конкретных CVE: PHPUnit, Log4Shell, Confluence, Citrix, F5, TeamCity и
ещё около двухсот. Сигнатуры взяты из правил виртуальных патчей CrowdSec, лежат в образе и обновляются с
NginxionS.

- **Минимальная критичность** — сигнатуры ниже не используются.
- **Максимальное влияние на скорость** — «Низкое» оставляет только самые быстрые сигнатуры.
- **Сигнатуры с года** — уязвимости раньше этого года не проверяются.
- **Действие для высокой, средней и низкой уверенности** — блокировать, только записать, выключено или как
  режим движка.

Событие называется «IPS Signature '…' Found», в нём есть номер CVE.

### Anti-Bot: проверка браузера

Посетитель получает короткую страницу проверки. Браузер решает задачу (proof-of-work), собирает отпечаток и
получает cookie, после чего сайт открывается как обычно. Скрипты, headless-браузеры и Selenium проверку не
проходят. Поисковые и другие проверенные боты её не получают.

- **Страницы, где браузер проходит проверку** — по одному пути в строке, например `/`, `/login`. Если это поле
  и поле ниже пусты, проверка идёт на всех страницах хоста.
- **Пути, которым нужна пройденная проверка** — например `/api/login`. Запрос без cookie отклоняется, а
  открытие такой страницы в браузере показывает проверку.
- **Режим «Обнаружение»** проверку не показывает. Запросы без cookie на обязательных путях проходят, но
  записываются в события. Так можно понять, сколько их, прежде чем включать блокировку.

Работает в AppSec CrowdSec. Нужен включённый баунсер CrowdSec: «CrowdSec → Настройки → Баунсер».

### Schema Validation: запросы по OpenAPI

Запросы к API проверяются по его описанию OpenAPI 3 или Swagger 2.0: путь, метод, параметры, тело.

1. Практика → Schema Validation → **Загрузить файл OpenAPI** (YAML или JSON, до 5 МБ). Файл сразу отмечается.
2. **Что проверяется:**
   - «Весь API» — запросы к путям, которых нет в файле, тоже отклоняются;
   - «Только пути из файлов» — остальные пути не проверяются.
3. Режим «Обнаружение» на время проверки: несоответствия видны в событиях, запросы проходят.

Файл, который использует практика, удалить нельзя. Повторная загрузка с тем же именем заменяет его, и
CrowdSec применяет новый файл.

### File Security: антивирус для загрузок

Тело загрузки (POST, PUT, PATCH) проверяет ClamAV до того, как оно попадёт на сервер. Вирус отклоняется со
страницей блокировки или, в режиме «Обнаружение», только записывается.

- **Действие по уверенности:**
  - высокая — вредоносное ПО;
  - средняя — потенциально нежелательные программы (PUA);
  - низкая — эвристика (по умолчанию только запись).
- **Наибольший размер проверяемой загрузки** (10 МБ по умолчанию) и **действие для загрузки крупнее** — она не
  проверяется. «Как у движка» в блокировке отклоняет такие загрузки: увеличьте предел, если загружаете
  большие файлы.
- **Наименьшая критичность вируса** (по умолчанию «средняя»): критичность берётся по виду вредоносного ПО в имени
  сигнатуры. Шифровальщики, бэкдоры, эксплойты, черви — критическая; трояны, загрузчики, шпионы — высокая;
  эвристика, фишинг, тестовые файлы — средняя; PUA и реклама — низкая.
- **Файл без имени** — двоичная загрузка без имени файла (нет `filename` в `Content-Disposition`, путь не кончается
  именем файла). «Как у движка» в блокировке отклоняет такие загрузки, даже чистые: если ваше API принимает
  двоичные данные без имени, поставьте «Обнаружение» или «Выключено». Формы, JSON и текст файлами не считаются.
- **Архивы:** по умолчанию архив не распаковывается и проходит без проверки. Включите **распаковывать и проверять
  архивы** — ClamAV проверит содержимое архивов до заданного размера; отдельные действия — для архива внутри
  архива и для архива, который не удалось распаковать (зашифрован паролем или слишком велик).
- **Эмуляция угроз** — в NginxionS это углублённый статический анализ ClamAV вместо песочницы Check Point:
  документы Office с макросами, повреждённые исполняемые файлы и медиа отклоняются как находки высокой уверенности.

ClamAV работает в своём контейнере, и только пока File Security включён хотя бы у одного хоста: его сигнатуры
занимают около 1 ГБ памяти. После включения он минуту-две загружает сигнатуры, загрузки в это время проходят.

**Агенты → open-appsec → Агент → File Security:**

- состояние ClamAV и версия сигнатур;
- **Загрузить сигнатуры** — файлы `main.cvd`, `daily.cvd`, `bytecode.cvd`, скачанные на другой машине (без
  интернета);
- **Обновлять сигнатуры через интернет** — freshclam, если у сервера есть выход в интернет.
