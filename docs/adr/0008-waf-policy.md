# ADR-0008. Политика open-appsec из объектов

**Статус:** принято (фаза 5). **Дата:** 2026-10-29.

## Контекст

До фазы 5 NPMOS генерировал `local_policy.yaml` в синтаксисе v1beta1, как open-appsec-npm: на каждый защищённый хост — своя практика и свой триггер, всё остальное — экспертными YAML-фрагментами. Нужен конструктор политики в GUI (практики, ограничения частоты, журналирование, ответы, исключения, доверенные источники) без ручного YAML.

Что показали исходники агента (`reference/openappsec/components/security_apps/local_policy_mgmt_gen`) и проверка на живом агенте:

- Агент читает файл сначала как v1beta2, затем как v1beta1.
- **v1beta2 применяет только первое исключение правила** (и первую практику, первый триггер), v1beta1 — все исключения. Исключения v1beta1 — списки по ключам (`sourceIp: [..]`); поле `condition` в v1beta1 игнорируется, и такое исключение срабатывало на всё (старый smoke-тест проходил ложно).
- Только в v1beta2: ограничения частоты (access control), ответ-перенаправление, IPS и проверка файлов (последние два — Premium-версия агента).
- В v1beta1 у защит CSRF / раскрытия ошибок / открытого перенаправления нет «как у правила»; open-appsec-npm писал ключи `csrf-protection`, которые агент не читает (`csrf-enabled`). Защиты молча оставались выключенными.
- В v1beta2 оба ключа `threatPreventionPractices` и `accessControlPractices` обязательны в каждом правиле; пустой список берёт практики правила по умолчанию.
- Ограничение частоты агент хранит по имени практики: если одна практика стоит в нескольких правилах, действует только последнее. И оно не работает для хоста без схемы (`example.com`), а хосты локальной политики — без схемы (иначе правило привязано к одному порту).

## Решение

- **Объекты** хранятся в `npmos_waf_object` в терминах v1beta2 (`kind`, `name`, `spec`). Спецификация дополняется значениями по умолчанию и проверяется JSON-схемой агента (`schema-v1beta2.json`). Встроенные объекты `npmos-*` (рекомендуемая, строгая и API-практики, «без ограничения частоты», журнал, ответы 403 и страница блокировки) создаются при старте, обновляются вместе с NPMOS и не редактируются, только копируются.
- **Шаблоны** — наборы встроенных объектов с режимом: рекомендуемый, строгий, только наблюдение, API.
- **Политика по умолчанию** — настройка `waf.policy` (режим и id объектов). Хост ссылается на шаблон, на свои объекты (`npmos_waf_host.objects`) или наследует политику по умолчанию. Исключения хоста добавляются к исключениям политики по умолчанию. Минимальная уверенность хоста — производная практика `<практика>.<уверенность>`. Имена правил прежние (`npm-managed-specific-rule-proxyhost-<id>`), импорт open-appsec-npm работает как раньше.
- **Формат файла:** v1beta1, пока политика не использует то, что есть только в v1beta2. Иначе v1beta2, и GUI предупреждает о правилах с несколькими исключениями. В v1beta1 защиты «как у правила» получают копию практики под режим правила (`<практика>.<режим>`). В v1beta2 у каждого правила, кроме первого, использующего практику с ограничениями частоты, — своя копия (`<практика>.<n>`). Ссылки на несуществующие объекты (экспертный фрагмент после переименования) показываются предупреждением.
- **Агент:** патч `0002-rate-limit-hosts-without-scheme.patch` — у хоста без схемы путь правила берётся от первого `/`.
- **Экспертные фрагменты** принимаются в любом синтаксисе, переводятся в термины v1beta2 и сливаются с собранной политикой.
- **Изменения:** у каждого изменения есть предпросмотр (проверка, diff `local_policy.yaml`, формат, предупреждения). Изменение применяется сразу. После каждого изменения сохраняется версия: снимок объектов, политики по умолчанию и объектов хостов. Откат сопоставляет объекты по виду и имени и переносит ссылки на текущие id. Импорт YAML (v1beta1/v1beta2) сначала показывает план, правила хостов не импортирует. Экспорт — в v1beta2 или v1beta1.
- **API:** `/api/npmos/waf/policy/{objects,default,preview,versions,export,import}`, права `waf_policy:view/manage`. Спецификации передаются как есть (`webAttacks`, `local-tuning`), поэтому у GUI для этого API свой клиент без преобразования ключей.

## Последствия

- open-appsec-npm и старые экспертные фрагменты продолжают работать. Исключения v1beta1 теперь действительно ограничены своими условиями.
- Ограничения частоты требуют патченого агента (образ `npmos-appsec-agent`), проверяются в smoke-тесте CI.
- Правила по локациям наследуют объекты хоста; свои объекты у локации — позже, при необходимости.
