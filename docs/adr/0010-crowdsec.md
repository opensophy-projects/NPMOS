# ADR-0010. CrowdSec под управлением NPMOS, без cscli и без облака

**Статус:** принято (фаза 7). **Дата:** 2026-10-29.

## Контекст

CrowdSec в стеке с фазы 0: официальный образ, тома наполняются офлайн-снимком hub из образа NPMOS, CAPI выключен, ключи двух баунсеров (`npmos` — nginx, `appsec` — агент open-appsec) создаёт `npmos-init`. Настраивать его можно было только `cscli` и правкой файлов, баунсер nginx — правкой `/data/crowdsec/crowdsec.conf`. Нужно управление целиком из GUI (ADR-0) и без интернета.

Что показал CrowdSec v1.8.1 на стенде:

- LAPI регистрирует машину без `cscli`, если в `api.server.auto_registration` задан токен: `POST /v1/watchers` с `registration_token` → машина сразу подтверждена. Повторная регистрация того же имени — 403.
- Вход машины (`/v1/watchers/login`) отвергается, если User-Agent не вида `имя/версия` (Node по умолчанию шлёт `node`).
- У LAPI нет API для списка машин и баунсеров: `cscli` читает их из базы (`crowdsec.db`, SQLite, WAL).
- Решения по сценарию снимаются `DELETE /v1/decisions?scenario=…`; ручные баны — алерт с решениями от машины (как `cscli decisions add`).
- Индекс hub с `--with-content` содержит содержимое всех элементов; установка = файл в `hub/<path>` + симлинк в `<тип>/[<стадия>/]<файл>`, версия определяется по sha256 файла (у версий бывают одинаковые digest). Файлы данных (GeoIP, списки) скачиваются отдельно.
- `config.yaml.local` CrowdSec накладывает поверх `config.yaml`; стартовый скрипт образа его не трогает.
- Ошибка в профиле или файле CrowdSec → процесс завершается, Docker перезапускает контейнер (растёт `RestartCount`).
- Парсер `crowdsecurity/whitelists` не пускает в сценарии частные адреса: в закрытом контуре все клиенты частные.
- Lua-баунсер NPMplus стоит на всём http-контексте nginx, включая интерфейс NPMOS (порт 81).

## Решение

- **Тома CrowdSec монтируются в `npmos`** по тем же путям (`/etc/crowdsec`, `/var/lib/crowdsec/data`): симлинки hub разрешаются в обоих контейнерах. NPMOS пишет только свои файлы: `acquis.d/npmos.yaml`, `profiles.yaml`, `parsers/s02-enrich/npmos-allowlist.yaml`, `scenarios/npmos-openappsec-prevent.yaml`, `config.yaml.local`. Чужие (локальные) файлы не трогаются.
- **Машина NPMOS** `npmos-<sha256(пароля)[0:12]>`: пароль и токен регистрации создаёт `npmos-init` (секреты `crowdsec_machine_password`, `crowdsec_registration_token`), имя из пароля не конфликтует с прошлыми регистрациями. Машины и баунсеры читаются из `crowdsec.db` только на чтение.
- **Настройки** (`npmos_setting` «crowdsec») → файлы → перезапуск `crowdsec` через `npmos-control`. Успех — LAPI отвечает дважды с паузой и `RestartCount` не вырос; иначе прежние файлы возвращаются, CrowdSec перезапускается ещё раз, в GUI — фатальная ошибка из его журнала, настройки в БД тоже откатываются. Применения идут по одному.
- **Hub без cscli** (`crowdsec/hub.js`): список с состоянием (актуален/устарел/изменён/локальный), установка с зависимостями коллекций, удаление с сохранением того, что нужно другим коллекциям, обновление до индекса. Без интернета файлы данных должны уже быть (снимок образа или загруженный архив `scripts/crowdsec-hub-snapshot.sh`); онлайн — только опцией «Разрешить онлайн-обновление hub» (CDN CrowdSec, таймаут 60 с). Индекс отдаётся контейнеру CrowdSec самим NPMOS на внутреннем порту 7480 (не публикуется): его ежедневный `cscli hub update` больше не уходит наружу.
- **Источники:** журналы nginx (`type: npmplus`, коллекция `ZoeyVid/npmplus`), журнал open-appsec (`type: openappsec`, парсер `openappsec/openappsec-logs`), AppSec CrowdSec (`0.0.0.0:7422`). Сценарий NPMOS: N запросов одного IP, заблокированных open-appsec за M минут → бан по профилям (leaky bucket; триггер при N = 1). Сценарии `openappsec/*` из hub (бан за каждое событие) не ставятся.
- **Профили** — список NPMOS (область, сценарии, выражение, бан/капча, срок, эскалация `duration_expr`); без включённых — профиль-заглушка (CrowdSec не стартует без профиля). **Белый список** — парсер-whitelist (IP, CIDR, выражения) + переключатель «Не банить частные адреса» (парсер `crowdsecurity/whitelists`); адреса белого списка не попадают и в блок-листы.
- **Баунсер NPMOS:** `/data/crowdsec/crowdsec.conf` и `conf.d/crowdsec.conf` пишет NPMOS (прежний файл NPMplus сохраняется как `crowdsec.conf.npmplus`), nginx перезагружается, конфигурацию, которую nginx отверг, NPMOS откатывает. В Lua-код NPMplus добавлена проверка `$npmos_crowdsec_off`: хосты исключаются из таблицы «Хостов» (`set` в `_common.conf`), порты интерфейса NPMOS и GoAccess исключены по умолчанию (`map $server_port`) — бан не лишает администраторов GUI; проверку интерфейса можно включить.
- **Алерты** LAPI каждые 30 с → `npmos_security_event` (`kind = crowdsec`, позиция — `npmos_log_cursor` «crowdsec:alerts» в той же транзакции): «События», аналитика (KPI «Банов CrowdSec»), уведомления. Алерты ручных банов и блок-листов в события не идут — они в журнале аудита.
- **Блок-листы** вместо community blocklist: файл (до 20 МБ, 200 000 адресов) или URL по расписанию (таймаут 30 с, опция без проверки TLS для узла с самоподписанным сертификатом). Решения блок-листа — сценарий `npmos/blocklist/<id>`, при обновлении заменяются. **Обмен между узлами:** `/api/npmos/crowdsec/public/decisions` с Bearer-токеном (в БД — только sha256) отдаёт собственные баны узла (без импортированных — нет петель); другой узел подключает его как блок-лист по URL.
- **CAPI не используется** и в GUI не включается: регистрация в облаке противоречит local-first, замену дают блок-листы и обмен между узлами.
- **Права:** `crowdsec:view`, `crowdsec:decide` (баны, разбаны, обновление блок-листов), `crowdsec:manage` (настройки, hub, блок-листы, хосты).

## Последствия

- CrowdSec полностью обслуживается из GUI: раздел «Безопасность → CrowdSec», колонка CrowdSec в «Хостах», «Забанить IP» в карточке события. `cscli` и правка файлов не нужны.
- Изменение настроек перезапускает CrowdSec (5–10 с без решений для новых адресов в режиме live; сами решения хранятся в базе и сохраняются).
- Обновление CrowdSec (новый образ) может поменять формат файлов: генераторы покрыты тестами, ошибка старта откатывается.
- Позже: CAPI-подобная синхронизация сигналов между узлами (сейчас — только решения), уведомления CrowdSec (`notifications/*`), уровни симуляции сценариев (`simulation.yaml`), удаление устаревших машин (нужна запись в базу CrowdSec).
