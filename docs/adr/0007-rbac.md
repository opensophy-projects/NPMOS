# ADR-0007. RBAC: роли поверх прав NPMplus

**Статус:** принято (фаза 3). **Дата:** 2026-10-28.

## Контекст

В NPMplus права пользователя — флаг `admin` в `user.roles` и одна строка `user_permission`: видимость (`user` / `all`) и `hidden` / `view` / `manage` для шести разделов (прокси, редиректы, 404, потоки, списки доступа, сертификаты). Проверки — JSON-схемы в `lib/access/*.json`, которые читает `access.can()`. Пользователи, журнал аудита и настройки доступны только администратору.

NPMOS нужны роли с правами на свои разделы (WAF, PKI, CrowdSec, обучение, сервисы…), встроенные роли (Administrator, Operator, Security Analyst, Viewer), OIDC-группы → роли, и всё это без переписывания upstream-кода (правило «крючков»).

## Решение

- **Таблицы:** `npmos_role` (имя, описание, `builtin`, `scope` = `all` / `own`, `oidc_groups`), `npmos_role_permission (role_id, resource, action)`, `npmos_user_role (user_id, role_id)`.
- **Модель** (`npmos/backend/npmos/rbac/model.js`): ресурсы и действия (`view` / `manage` + особые: `pki:issue`, `pki:revoke`, `pki:export_key`, `waf_policy:apply`, `waf_learning:label`); любое действие включает `view`. Права встроенных ролей задаются в коде и обновляются вместе с NPMOS; в БД у них редактируются только OIDC-группы.
- **Роли — источник прав.** Права нескольких ролей складываются; область «все хосты», если она у любой из ролей.
- **Administrator = флаг `admin` upstream.** Назначение роли ставит или снимает флаг. Последний администратор роль не теряет.
- **Адаптер — два крючка в `lib/access.js`:**
  1. при загрузке пользователя права берутся из ролей (`rbac.resolve`). `user_permission` переписывается как их проекция, если отличается. Upstream-схемы и UI, читающие `user_permission`, работают без изменений;
  2. в `can()` метки ресурсов NPMOS (`waf_policy:manage`…) решает RBAC. Роли открывают разделы, бывшие только для администратора: пользователи (`users:*`), журнал (`audit_log:view`), настройки (`settings:*`). Действия над администраторами остаются за администраторами. Остальное решает схема upstream.
- **Права по пользователям** (`users:permissions`, окно «Права» upstream) заменены ролями: менять их может только администратор, и при следующем запросе пользователя они снова выравниваются по ролям.
- **Эскалация:** нельзя создать, изменить, назначить или снять роль с правами, которых нет у себя. Роль Administrator назначает только администратор.
- **Миграция:** строки `user_permission` неадминистраторов превращаются в роли. Пользователи с одинаковыми правами получают общую роль («NPMplus user» для прав по умолчанию), поэтому права ни у кого не меняются.
- **OIDC:** настраиваемый claim с группами (по умолчанию `groups`), по желанию — scope `groups`. Если хотя бы у одной роли указаны группы, роли пользователя при входе следуют группам IdP.

## Последствия

- Upstream-код не переписан: две метки `NPMOS:` в `access.js`, крючки в `routes/oidc.js`, `HasPermission` (prop `rbac`) и на трёх страницах администрирования.
- Новый пользователь без роли входит, но ничего не видит. После создания пользователя UI сразу предлагает назначить роли.
- Область «конкретные хосты» (ROADMAP, фаза 3: «позже») добавляется отдельной таблицей привязок без изменения этой модели.
